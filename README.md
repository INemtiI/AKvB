# AKvB — Аудиомодем XXI века 🔊

**Передача файлов между устройствами обычным звуком** — из динамика в микрофон.
Без интернета, Bluetooth, кабелей и серверов. Целостность каждого байта подтверждается SHA-256.

> 🌐 **Живое демо:** https://inemtii.github.io/AKvB/ — откройте на двух устройствах, и одно передаст файл другому через воздух. После первой загрузки страница работает полностью офлайн (можно включить авиарежим).

---

## Возможности

- 📁 **Передача любых файлов и текста** между любыми устройствами с динамиком и микрофоном
- ✅ **Гарантия целостности**: SHA-256 всего файла + CRC32 каждого 64-байтового блока; приёмник показывает, какие блоки повреждены
- 🤝 **Авто-согласование режима**: передатчик объявляет параметры служебной посылкой — на приёмнике ничего настраивать не нужно
- ⚙️ **Настраиваемый физический уровень**: 2 / 4 / 8 / 16-FSK, длительность символа 40–300 мс, три частотных пресета + ручная настройка частот со встроенным валидатором
- 🎯 **Следящий декодер** (early-late tracking): компенсирует расхождение частот дискретизации устройств — длинные передачи не разваливаются
- 📱 **Два равноправных клиента**: Python CLI и одностраничное веб-приложение (работает на телефоне, ноутбуке — где угодно), форматы полностью совместимы
- 🚫 **Ноль внешних запросов**: веб-версия — один самодостаточный HTML-файл

## Быстрый старт

### Вариант 1: веб-приложение (проще всего, работает на телефоне)

1. Откройте https://inemtii.github.io/AKvB/ на двух устройствах (или запустите локально: `python -m http.server` и откройте `http://localhost:8000`)
2. На приёмнике: вкладка **ПРИЁМ** → **ЗАПИСЬ** (разрешите доступ к микрофону)
3. На передатчике: вкладка **ПЕРЕДАЧА** → выберите файл или введите текст → **ПЕРЕДАТЬ**
4. Приёмник сам определит режим, декодирует файл, проверит SHA-256 и предложит сохранить

### Вариант 2: Python CLI

```bash
pip install -r requirements.txt   # numpy, sounddevice

# приёмник (слушает 60 секунд, всё определяет сам)
python src/file_receiver.py --duration 60

# передатчик — режим по умолчанию (4-FSK, 100 мс, проверен в воздухе)
python src/file_sender.py --file photo.jpg

# быстрый режим (50 бит/с, нужна тишина)
python src/file_sender.py --file doc.pdf --mode 8 --preset wide --symbol-ms 60

# неубиваемый режим для шумной комнаты
python src/file_sender.py --text "Привет!" --mode 2 --symbol-ms 200
```

Веб- и Python-версии совместимы в обе стороны: можно передавать с телефона (сайт) на ноутбук (CLI) и наоборот.

## Скорость и режимы

| Режим | Скорость | Когда использовать |
|---|---|---|
| 2-FSK, 200 мс | 5 бит/с | шум, большое расстояние, худшие условия |
| **4-FSK, 100 мс (по умолчанию)** | **20 бит/с** | проверенный баланс скорости и надёжности |
| 4-FSK, 80 мс, high | 25 бит/с | тихая комната, хорошая аппаратура |
| 8-FSK, 60 мс, wide | 50 бит/с | тишина, устройства рядом |

Приёмник всегда одинаковый — режим он узнаёт из служебной посылки.

## Как это работает (в двух словах)

```
файл → кадр AM01 (SHA-256 + блоки с CRC32) → биты → FSK-тона → 🔊 ... 🎤 → декодер → файл + вердикт
```

1. Файл упаковывается в **кадр AM01**: заголовок (имя, размер, SHA-256) + блоки по 64 байта с CRC32.
2. Биты кодируются **FSK-тонами** (каждый символ — одна из 2/4/8 частот), кадр обрамляется маркерным тоном.
3. Перед данными в неизменном **базовом режиме** летит 15-байтовая служебная посылка с параметрами — приёмник сам перестраивается.
4. Приёмник находит маркер, синхронизируется с точностью до долей символа, декодирует данные **следящим декодером** и проверяет CRC32 + SHA-256.

Подробности: [архитектура](docs/ARCHITECTURE.md) · [протокол](docs/PROTOCOL.md) · [тестирование](docs/TESTING.md)

## Тесты

```bash
python tests/test_nego_loopback.py   # все режимы, согласование, legacy, дрейф часов ±0.25%
python tests/test_file_loopback.py   # файловый тракт: кадр → сигнал+шум → файл
python tests/test_loopback.py        # текстовый режим
node tests/test_webapp.js            # JS-реализация + сверка SHA/CRC с эталонами Node
```

Все тесты — «математический loopback»: сигнал генерируется, зашумляется и декодируется без звука, поэтому работают в любом CI.

## Ограничения

- Скорость ограничена акустикой: 5–50 бит/с (килобайт — от ~3 до ~27 минут). Это принципиальный компромисс надёжность/скорость для звукового канала
- Дистанция: уверенно 0.2–1 м; дальше — снижать скорость и повышать громкость
- Сильный шум и эхо ухудшают приём (лечится выбором режима: 2-FSK + длинный символ)
- Прямой коррекции ошибок (FEC) нет: битый блок виден в отчёте, но требует повторной передачи
- Микрофон в браузере требует HTTPS или localhost (ограничение браузеров, не наше)

## Обновление: разгон канала (16-FSK, ASCII-7, сжатие картинок)

- **16-FSK** — 4 бита на символ: при 60 мс/символ ≈ 66 бит/с (в 3.3 раза быстрее базовых 20 бит/с). Требует пресет частот `ultra` (тона 1400–5300 Гц, маркер 6100) — сайт и `file_sender.py` выбирают его автоматически. Режим требователен: тишина, устройства рядом, громкость 70–80%.
- **10-FSK не добавлен сознательно**: log₂(10) ≈ 3.32 бита на символ — дробное число бит требует арифметического кодирования через границы символов, а выигрыш к 8-FSK всего ~11% при заметно худшей помехоустойчивости. 16-FSK даёт честные 4 бита и на 33% быстрее 8-FSK.
- **Кодировка ASCII-7** — латиница, цифры, скобки и все стандартные знаки упаковываются по 7 бит на символ: текст на 12.5% быстрее UTF-8. Выбор кодировки — на сайте (КОДИРОВКА ТЕКСТА) и в CLI: `--text --encoding ascii7`. Не-ASCII текст автоматически уходит в UTF-8 с предупреждением.
- **Картинки** — это бинарные данные, 7-битная упаковка их не сжимает. Реальное ускорение — сжатие на сайте перед отправкой: селектор КАРТИНКИ уменьшает фото до 320/480/640px и кодирует в JPEG прямо в браузере (интернет не нужен). Типичное фото 3 МБ → 15–30 КБ.

| Режим | Скорость | Условия |
|---|---|---|
| 16-FSK, 60 мс, ultra | ~66 бит/с | тишина, устройства вплотную |
| 16-FSK, 40 мс, ultra | 100 бит/с | экспериментально, идеальные условия |
